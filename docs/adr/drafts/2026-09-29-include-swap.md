# [DRAFT] 取り込み中の @include の取り込み先を替える・一括の相手を絞る・共通部らしい図のパスを推す

- ステータス: ドラフト(未採番。承認後 /adr で正式登録)
- 日付: 2026-09-29
- 起点: BLK-primary-20260929-2108-friction(共通部を rte.sb と hal.sb に分けたあと、12 枚の構成図の @include を差し替えるのにクリック 96)

## コンテキスト
共通部を別の共通部に替える手段が「外す → 取り込む」しか無く 1 図ずつで、足すと本文の先頭側に入る。「すべてに取り込む」は共通部を使っていない図
(データフロー図)にも入る。「.sb 読込」で選んだ図はフォルダを持たないので、誰も取り込んでいない rte.sb の候補パスが `rte.sb` になる。

## 選択肢
1. 取り込み中の行の下に「替える…」(一緒に読み込んだ図の選択)と「同じ共通部を取り込んでいるほかの N 枚も替える」(既定で入)を置き、行をその場で書き換える
2. 新しい「共通部の差し替え」ダイアログ(元 → 先、対象の図の一覧)
3. 図名の改名(共通部の図の名前を変える)で済ませる

## 決定
案 1。既存の欄の中で完結し(principles「新しい画面・ボタンを増やす前に既存機能の入口を直す」)、ID 改名・図名の改名と同じく
「1 か所で直すと一緒に読み込んだ図すべてに揃う・Ctrl+Z 1 回で戻る・変わった図は .sb 保存で一緒に出る」。案 3 は共通部を 2 つに分ける用途に合わない。
一括の相手は、表示中の図が何かを取り込んでいればそのどれかを取り込んでいる図だけ(「同じ共通部の図へ」)、何も取り込んでいなければ全部(「全図に取り込む」)。
候補パスは、候補の図が「共通部らしい」(自分は何も取り込まず、同じフォルダの図が接続で指して自分では定義していない ID を定義し、取り込む側の図と同じ ID を定義しない)
ときに限り、隣の共通部を取り込んでいる書き方のフォルダ部分を付ける。フォルダを持たないキーでは構成図・データフロー図と共通部を本文でしか見分けられないため。
足す候補の並びは、自分と取り込み済みの図が既に持つ ID を重ねて持ち込む図を後ろに回す。判定は core/check(includeSwapCandidates / planIncludeSwap / includeAddTargets)。

## 影響
- 「すべてに取り込む」の名前が「全図に取り込む」/「同じ共通部の図へ」になる(語彙 add-include-all / add-include-same)
- 替えた行は元の位置のまま(差分 1 行)。既に替え先を取り込んでいる図・循環になる図は替えず、知らせに名前を出す
