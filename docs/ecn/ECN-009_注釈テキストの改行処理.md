# ECN-009: 注釈テキストの改行処理

- **ステータス**: 解決済
- **対象コミット**: `f70f277`, `9df9651`
- **影響ファイル**: `stableblock.html`, `vscode-stableblock/src/extension.js`

## コンテキスト

注釈（ノート）テキストで改行が正しく扱われず、複数の不具合が発生していた。

## 問題の詳細

1. **Enterキーでバックスラッシュ表示**: textarea内でEnterを押すと改行ではなくバックスラッシュが表示された
2. **再表示時に `\n` リテラル表示**: 保存されたノートを再度開くと改行位置に `\n` という文字列がそのまま表示された
3. **通常モードでの注釈追加ボタン表示**: 注釈編集モード以外でも「+ 注釈追加」ボタンが表示されていた

## 問題の原因

### 改行→DSL変換

DSL上では改行を `\n`（2文字リテラル）で表現するが、textarea入力時の実改行→DSL変換関数が存在しなかった。

### DSL→改行変換

textareaの初期値設定で `split('\\\\n')` を使用しており、3文字の `\n`（バックスラッシュ+バックスラッシュ+n）にマッチしようとしていた。実際のDSLには2文字の `\n` が格納されているため、splitが機能しなかった。

## 対策

### 専用の変換関数を追加

`setNoteLabel()`/`sNLb()` を新設し、textarea内の実改行をDSL形式の `\n` に変換する。

```javascript
// 実改行 → DSL \n
value.replace(/\n/g, '\\n')
```

### split引数の修正

```javascript
// 変更前: 3文字マッチ（不正）
item.label.split('\\\\n')

// 変更後: 2文字マッチ（正）
item.label.split('\\n')
```

### ボタン表示制御

「+ 注釈追加」ボタンを通常モードのツールリストから除外し、注釈編集モード時のみ表示するように変更。

## 結果

- 改行を含むノートテキストが正しく保存・復元される
- textarea上での改行入力・表示が自然に動作
- 通常モードでの誤操作が防止される
