# [DRAFT] 入れ子の group は座標で決まるまま、GUI の操作で親を広げ・兄弟を押し出して子を内側に保つ

- ステータス: ドラフト(未採番。承認後 /adr で正式登録)
- 日付: 2026-09-26
- 起点: BLK-owner-20260926-0451-1(入れ子の group を作図 UI だけで組めない)

## コンテキスト
.sb の group には「子」の記述が無く、要素が group の矩形の内側にあればその group の子になる(描画・ドラッグ連動・検査のすべてが座標で判定)。
このため GUI の操作で子が親の枠をまたぐと、画面上どこに属するかが曖昧になる。批評で当たった症状:
「選択をグループ化」の新しい group が親の枠や上の段の block に重なる、矢印キーで子を下へ動かしても親が広がらない、
子 group が親からはみ出していると「+ グループ内にブロック追加」が子 group の中や枠の上に置く。どれも警告が出ない。

## 選択肢
1. DSL に親子を書く(`group a ... in b` など)。書式の変更で既存の図・書き出し・往復テストすべてに波及する
2. 座標のまま、はみ出しを警告するだけ(直すのは利用者)
3. 座標のまま、GUI の操作(移動・大きさ変更・グループ化・group 内への追加・貼付)の前に親を控え、操作の後で子が控えた親の枠を
   またいだら、越えた向きに親(と親の親)を広げる。広がった group が兄弟に掛かるなら、その兄弟を同じ向きへ元の隙間(1 グリッドまで)を
   保って押し出す。親の外へ出切った要素は親から出たものとして扱う。これに加えて、枠をまたぐ配置は検査の警告にする

## 決定
案 3。書式を変えず、本文の差分は広がった・押し出された要素の座標・大きさの行だけ(principles「正本とレイアウト」)。
draw.io / Visio のコンテナが子を入れると広がるのと同じ手触りにしつつ、黙って兄弟を子に取り込むこと(座標判定の副作用)を押し出しで防ぐ。
本文欄で直接書いた配置は変えず、警告(`block「x」が group「g」(Ln)の枠をまたいでいる`)で知らせる。
計算は `core/layout`(parentMap / fitParents / groupRectFor / placeInGroup / lastChildBlock)と `core/check`(findStraddles)に置き、
HTML 版と VSCode 拡張の webview が同じ関数を呼ぶ。

## 影響
- ドラッグで要素を親の枠の上に落とすと親が広がる。親から出したいときは枠の外まで動かす
- 「選択をグループ化」の余白は、上の段や隣の要素に掛かるなら 1・0 に詰める(ラベルは 1 グリッドの帯に収まる)
- 押し出しは group の中身ごと動かす。押し出した要素がさらに別の要素に掛かれば、それも押す
