# [DRAFT] キャンバスの自動拡張は既定のまま、図ごとに `@canvas ... grow=off` で止め、広げた直後に元の寸法へ戻せる

- ステータス: ドラフト(未採番。承認後 /adr で正式登録)
- 日付: 2026-09-26
- 起点: BLK-human-20260926-1010-1(v0.8 所感: キャンバスの自動拡張が、資料のサイズに合わせて設計したキャンバスを勝手に広げる)
- 前提: `2026-09-25-canvas-grow-and-fit.md`(GUI の操作ではみ出したときだけ `@canvas` 行を広げる)

## コンテキスト
v0.8 で GUI の操作ではみ出すとキャンバスが自動で広がるようになった。キャンバスを A4 横・スライド 1 枚などの資料の寸法に
合わせて描く人は、広がるたびに寸法を打ち直して戻す必要がある。人間の案は (a) 設定画面で自動拡張を切り替える、
(b) はみ出したときに拡張するかをポップアップで確かめる、(c) 拡張した後に元の寸法へ戻せる UI、の 3 つ。

## 選択肢
1. 画面の設定(localStorage / VSCode の設定)で自動拡張を切り替える — principles「GUI はテキストに無い状態を持たない」に反し、
   同じ .sb が開く人・形態によって違う動きをする。寸法を資料に合わせるのは図の性質なので、図に書くのが筋
2. はみ出すたびにポップアップで確かめる — ドラッグ・貼付・連続追加の途中で操作が止まる。新しい画面を増やす
3. 図ごとの属性 `@canvas ... grow=off`(既定は今のまま自動で広げる)+ 広げた直後に「元の寸法に戻して固定」を出す

## 決定
案 3。
- `grow=off` は `@canvas` 行の属性。core/dsl・HTML 版・拡張の parser が `canvas.grow` に読み、`core/layout` の `growCanvasInDsl` は
  grow=off の図を広げない。切替は HTML 版のツール欄「キャンバス (px)」のチェック「はみ出したら自動で広げる」と、
  拡張のツール欄 CANVAS の「Grow when items overflow」。本文の差分は `@canvas` 行の 1 属性(`setCanvasGrowInDsl`)
- 自動で広げたときは、ステータスバー(拡張は下端)に「キャンバスを広げた 400×300 → 700×300 [元の寸法に戻して固定]」を出す。
  押すと広げる前の寸法に戻し grow=off を書く(1 行の差分、元に戻すで戻る)。元に戻す・読込・新規・寸法の手入力で消える
- 既定は自動で広げるまま(principles「置いた要素はキャンバスに収まり」、junior の台本の手数を変えない)
- 固定した図ではみ出した要素は、core/check の `findOutside` がエラー欄に warn で出す(「キャンバス(400×300)の外に右へ 2 グリッド
  はみ出している。書き出しでは切れる」)。これは grow=off に限らず全ての図に効き、CLI の `npm run check` も同じ
- 画面のプレビューはキャンバスの外にはみ出した部分も描く(`svg { overflow: visible }`)。principles「DSL にあるものは全部見える」。
  書き出しはキャンバスの寸法で切れる
- 固定した図ではツール欄の寸法入力は要素より小さい値も受ける(はみ出しは警告で分かる)

## 影響
- `@canvas` の属性が 1 つ増える(`grow=off`。値は off だけを意味に持ち、それ以外・無しは自動で広げる)
- 旧版の StableBlock で開くと grow=off は無視され、今までどおり広がる(読めない行にはならない)
