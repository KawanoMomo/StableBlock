# [DRAFT] キャンバスは GUI の操作でだけ自動で広げ、配置・全体表示の計算は core/layout に置く

- ステータス: ドラフト(未採番。承認後 /adr で正式登録)
- 日付: 2026-09-25
- 起点: BLK-owner-20260925-1921-1(作図 UI だけでは図がキャンバスに収まらない)

## コンテキスト
`@canvas` の寸法は本文欄でしか変えられず、group の「＋ ブロック追加」で group が伸びるとキャンバスの外に切れた。
トップの「+ ブロック追加」「+ グループ追加」は常に 5,5 に重ねて置き、ズームは −/+ だけで全体表示が無かった。
HTML 版と VSCode 拡張の webview は同じ処理をそれぞれインラインで持っている。

## 選択肢
1. 描画だけを内容に合わせて広げ、`@canvas` は書き換えない(書き出しの寸法と画面が食い違う)
2. `@canvas` を内容に合わせて広げ・縮める(本文を開いただけ・要素を内側へ動かしただけで差分が出る)
3. GUI の操作(追加・移動・リサイズ・貼付・位置/寸法の入力)で要素がはみ出したときだけ `@canvas` 行の width / height を広げる。
   縮めない。読込・元に戻す・やり直し・本文欄の入力では触らない

## 決定
案 3。差分は `@canvas` の 1 行で、開いて保存するだけの往復は 1 バイトも変わらない(principles「正本とレイアウト」)。
縮めたいときはツール欄の「キャンバス (px)」で指定する(要素より小さくはできない)。
空き位置の探索(読み順・1 グリッド空け)、全体表示の倍率、−/+ の 0.25 刻みへの丸め、`@canvas` 行の書換は
`core/layout/layout-core.mjs`(browser 版は `layout-core.browser.js`、拡張は label-core と同じくインライン埋め込み)に置き、両形態で共用する。

## 影響
- `refresh()`(HTML)/ `notify()`(拡張)が既定で拡張を行う。本文をそのまま映す呼び出し(undo / redo / 読込)は `refresh(true)` / `notify(true)`
- 図を開いたとき(起動・読込)は全体表示の倍率(最大 100%)で見せる
