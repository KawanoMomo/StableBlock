# [DRAFT] 同じ 2 つの間の接続は向きごとに別の線として扱う

- ステータス: ドラフト(未採番。承認後 /adr で正式登録)
- 日付: 2026-09-29
- 起点: BLK-owner-20260928-2255-2(ECN-018 の 2 ブロック選択の接続管理パネルの拡張)

## コンテキスト
2 つを選んだ接続パネルは「同じ組の接続は向きを問わず 1 本」とみなし、先頭の 1 本だけを編集し、結ぶ入口も出さなかった。
本文に `B -> A "notify"` を足すと描画は 2 本になるのに、戻りの線のラベル・色・削除は作図 UI から触れなかった。
ソフト構成図・データフロー図では要求と応答を別の矢印で描くのが普通で、draw.io・Visio も同じ 2 図形の間に向きの違う線を何本でも引ける。

## 選択肢
1. 双方向(`-->`)に 2 つのラベルを持たせる(DSL の文法を増やす)
2. 向きごとに別の行(`A -> B`、`B -> A`)とし、パネルは向きごとに行を並べる。同じ向きは今どおり 1 本
3. 同じ向きの重複も含め何本でも許し、行番号で編集対象を決める

## 決定
案 2。理由: (a) DSL の文法を変えず、既存の図と書き出し(Mermaid・Excel・JSON Canvas)がそのまま往復する
(b) 行番号は @include 展開後の行と本文の行がずれるため編集の鍵にできない。from/to の向きで行を決める(core/label connLineIndex:
向きが一致する行を先に、無ければ双方向の逆の書き順の行)(c) 同じ向きの重複は今どおり作らない(chainConnectInDsl・右ボタンのドラッグ・Enter)。

## 影響
- 双方向の接続は両方の向きを持つとみなす(hasConnDir)。双方向がある組には逆向きを足さない
- 逆向きの片方向が別にある線の「⇄ 反転」「↔ 双方向」は同じ向きが 2 本になるため押せなくする(canFlipConn)
- 「接続を削除」はその向きの行だけを消す(以前は組の全行を消していた)
- HTML 版と VSCode 拡張の接続の書き換えは core/label の関数に寄せた(flip / bidir / prop / remove)
