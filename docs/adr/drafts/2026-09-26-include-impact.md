# [DRAFT] 共通部を動かした影響は、エラー欄に「読み込んだ時から増えた、ほかの図の診断」として出す

- 日付: 2026-09-26
- 課題: BLK-primary-20260926-1205-wish(同じ要望 BLK-junior-20260926-1205-wish)

## コンテキスト
共通部(`shared/common.sb`)を動かしたとき、それを @include している図のどこが横切り・重なりになるかは CLI の `npm run check` の
前後比較でしか分からなかった。owner の指定で新しい画面・ボタン・タブは増やさず、既存のエラー欄を広げる。

## 選択肢
1. 取り込んでいる図の診断を全部並べる。元からある警告に埋もれ、「この編集の影響」が読めない
2. 編集で増えた診断だけを並べる。比べる元を (a) 図を開いた時 (b) 最後に保存した時 (c) 読み込んだ時 のどれにするか
3. 取り込んでいる図のサムネイルを並べる(画面が増える。指定に反する)

## 決定
案 2(c)。core/check に `includersOf` / `addedDiagnostics` / `includeImpact` を置き、診断そのもの(parse・経路・ラベル)は
呼び出し側が渡す(core/check は import を持たない)。HTML 版は画面のエラー欄と同じ `checkIncluded` を渡すので CLI と同じ文になる。
比べる元は「.sb 読込」の時の本文(保存しても消えない。図を行き来しても消えない)。増えた診断のうち、発生源が共通部自身の行
(共通部の block 同士の重なり等)は共通部の欄に既に出るので数えない(12 枚に同じ行が 12 回並ぶのを避ける)。
編集前の診断は Map に持ち、打鍵のたびに測り直さない(12 枚 + 共通部で 1 回 1ms 未満)。

## 影響
- (改訂 2026-09-28、BLK-owner-20260926-2005-1)取り込み側の block の後に共通部の block が書かれている(@include が本文の後ろにある)図で、両者が重なると
  診断は共通部の行に付き、「発生源が共通部自身の行」で落ちていた。相手のある診断(重なり・またぎ・横切り・2 本目・ラベル・キャンバスの外・ID の重複)は
  `checkDiagram` が相手の行を refs に持ち、落とすのは発生源も相手も共通部の行のもの(共通部だけを開いても出る診断)に限る。相手が取り込み側の行なら
  取り込み側の図の診断として相手の行で出す(キャンバスの外は取り込み側の @canvas 行)
- 範囲は一緒に読み込んだ図だけ(CLI はフォルダ全体)
