# ECN-011: スナップガイドの表示と性能問題

- **ステータス**: 解決済（機能無効化）
- **対象コミット**: `d275dc5`, `c867b04`, `a660aed`
- **影響ファイル**: `stableblock.html`

## コンテキスト

ブロックドラッグ時にスナップガイド（位置揃えの補助線）を表示する機能を実装したが、3段階の問題が発生し、最終的に機能を無効化した。

## 問題の経緯

### 第1段階: ガイドが表示されない (`d275dc5`)

**原因**: スナップガイドのDOM要素を追加した直後に `renderSVG()` が呼ばれ、SVG全体が再構築されるためガイド要素が即座に破棄されていた。

**対策**: ガイドをDOM直接操作ではなく状態変数 `snapLines` に格納し、`renderSVG()` 内でSVG閉じタグ直前に描画する方式に変更。mouseup時に `snapLines=[]` でクリア。

### 第2段階: ドラッグのジッター (`c867b04`)

**原因**: 2つの問題の組み合わせ。
1. `dragSet` に `w`/`h` が含まれておらず、スナップ計算で `undefined` が使用された
2. 同一軸に複数のスナップ候補があった場合、全てが同時に適用され競合（発振）した

**対策**:
- `dragSet` に `w`, `h` を追加
- 各軸で最も近い1つのスナップのみ採用する `bestV`/`bestH` ロジックに変更

### 第3段階: 複雑な図でのドラッグ性能劣化 (`a660aed`)

**原因**: ドラッグの毎フレームで全ブロックとの位置比較が発生し、ブロック数が多い図ではフレーム落ちが顕著になった。

**最終対策**: スナップガイド機能全体を無効化（コード削除）。

```
削除内容:
- snapLines 状態変数
- renderSVG() 内のガイド描画
- onMove() 内のスナップ計算ロジック
- mouseup のガイドクリア処理
```

## 判断理由

スナップガイドの利便性と性能影響のトレードオフを検討した結果、複雑な図（多数のブロック）でのドラッグ操作の応答性を優先した。将来的にスナップガイドを再実装する場合は、空間インデックス（例: グリッド分割）による探索範囲の限定が必要。

## 結果

- ドラッグ操作が全ての図サイズで安定したフレームレートで動作
- スナップガイド機能は未提供（将来の再実装候補）
