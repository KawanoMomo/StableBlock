# [DRAFT] ID はプロパティ欄で決め、「ID補正」ボタンを畳む。改名ロジックは core/label に置く

- ステータス: ドラフト(未採番。承認後 /adr で正式登録)
- 日付: 2026-09-25
- 起点: BLK-owner-20260925-1921-4(ID を作図 UI で決められない)
- 関係 ECN: ECN-013(重複 ID の名前変更)、ECN-016(ID 自動生成補正)

## コンテキスト
ECN-016 は新規要素に `__new_N` を付け、ツールバーの「ID補正」でラベルから一括生成する方式にした。生成は小文字化と `_` の除去を行うので、
`Spi_Api` が `spiapi` になり、`Spi_Driver` のような表記で図間を参照する利用者の ID と揃わない。プロパティ欄の `BLOCK: id` は表示だけで、
ID を変えるには本文欄を触るしかなかった。接続行の書き換えは行全体への `\b` 置換で、ラベル内の同じ語も書き換えていた。

## 選択肢
1. 「ID補正」を残し、生成規則だけ大文字と `_` を保つ形に直す
2. プロパティ欄に ID 欄を置いて直接書けるようにし、新規要素(`__new_` と、この画面で自動で付けた ID)はラベルの入力に追従させ、「ID補正」を畳む
3. 2 に加えて、新規要素に最初から `__new_` でない ID を付ける

## 決定
案 2。ID を決める入口をプロパティ欄の 1 つにする(principles「1 つの機能に入口は 1 つ」)。読み込んだ図の ID はラベルを変えても動かさない
(図間の参照を壊さないため)。案 3 は paste・グループ化など `__new_` を前提にする箇所が多く、別に行う。
改名(`renameIdInDsl`)・生成(`labelToId`)・重複回避(`uniqueId`)・検証(`isValidId`)は HTML 版と VSCode 拡張で共通なので `core/label/label-core.mjs` に置き、
既存の browser build(`label-core.browser.js` / 拡張のインライン埋め込み)で両方から使う。改名は定義行と接続行の from / to だけを書き換える。

## 影響
- ツールバーから「ID補正」(拡張は「Fix ID」)が無くなる。Shift+クリックの全 ID 再生成も無くなる
- ID に使える文字は英数字と `_`(入力時の検証。既存の図の ID は読み込み時に制限しない)
- 複数の図にまたがる改名(primary の追記)は対象外
