# [DRAFT] 原点より左上(負の座標)の要素は読んで描き、描く範囲を左・上へ広げる。Excel だけ図全体をずらす

- ステータス: ドラフト(未採番。承認後 /adr で正式登録)
- 日付: 2026-09-30
- 起点: BLK-porter-20260930-0509(負の座標の group / block / note が「読めない」行になり描かれない)

## コンテキスト
既存の設計書の図には原点より左上へはみ出した配置がある。parser(core/dsl・HTML 版・VSCode 拡張)と check の書式は
座標を `[\d.]+` で読み、負号を受けないのでエラー行になり、その要素への接続も「ID が無い」になっていた。
描画(SVG / PNG)は `viewBox="0 0 W H"`、Excel はシートの左上からの絶対位置で置くので、負の座標はそのままでは切れる。

## 選択肢
1. 読み込み時に本文の座標を正の側へ書き換える(無変更保存がバイト一致しない。principles「正本とレイアウト」に反する)
2. 読むが、描く範囲は `@canvas` のまま(負の側は画面にも書き出しにも出ず、黙って欠ける)
3. 読み、描く範囲(`core/label` の `drawArea`)を原点より左・上の要素の端まで広げる。SVG は `viewBox` の原点を負にし、
   要素の座標はそのまま描く。PNG の画素数も同じ範囲。Excel はシートの外に置けないので、図全体を同じ量だけ右下へずらした写しから作る

## 決定
案 3。本文は書き換えない(無変更の往復はバイト一致)。その行は警告欄に「原点より左へ N・上へ M グリッド出ている(座標が負)」と出す
(core/check の `findNegative`。画面・VSCode 拡張・`npm run check` 共通)。
GUI で動かしても原点より左・上へは新たに出さないが、元から出ている要素は元の位置までは置ける(core/layout の `keepPos`)。
「元の位置」は動かし始めの位置でなく、本文(読み込み・本文欄の書換・元に戻す)に出た位置で、画面が要素ごとに覚える
(core/layout `noteFloors` / `posFloor`。右へ動かした後も ← で読み込んだ位置まで戻せる)。一緒に動かす要素(group とその中身、複数選択)は
`clampShift` の共通の量で動かし、どれかが下限に当たれば全員がその手前で止まる(枠だけ・中身だけが動かない)(BLK-owner-20260930-0608-1)。
画面の倍率換算は描いた SVG の `viewBox` から取る(`@canvas` の寸法ではない)。

## 影響
- `renderSvg` / `exportSvg` の `viewBox` と width / height、`exportPngSize` に渡すもの(`drawArea(parsed)`)、全体表示の倍率
- ラベルの自動配置の範囲(`placeLabels` の bounds)も `drawArea`
- Excel(`buildDrawingXml`)は `shiftToOrigin` でずらした写しを使う(負の座標が無い図はそのまま)
- 右・下へのはみ出しは今までどおり `findOutside` の警告で、描く範囲は広げない
