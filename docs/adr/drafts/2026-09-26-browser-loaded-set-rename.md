# [DRAFT] ブラウザ版の図をまたぐ参照探しと改名は「一緒に読み込んだ図」を範囲にする

- ステータス: ドラフト(未採番。承認後 /adr で正式登録)
- 日付: 2026-09-26
- 課題: BLK-primary-20260926-0451(差し戻し 1 回目: 横断の改名・参照探しが CLI と VSCode にしか無く、作図 UI に入口が無い)
- 関連: 2026-09-26-cross-diagram-rename.md(core/label の planRename を CLI と VSCode の F2 から呼ぶ)

## コンテキスト
HTML 版は file:// でも動く単一ファイルで、フォルダを勝手に読めない。書き込みもダウンロードしかない。
それでも作図 UI しか使わない利用者が、12 枚 + 共通部にまたがる ID の参照を探し、1 操作で改名できる必要がある。
owner の指定で、新しい画面・ボタン・タブは増やさない。

## 選択肢
1. File System Access API(showDirectoryPicker)でフォルダを開き、その場で書き戻す。Chromium 限定で、ネイティブの選択ダイアログは
   Playwright から操作できず、E2E とペルソナの実機確認ができない
2. 既存の「.sb 読込」(複数選択・@include 先を一緒に選ぶ)で読み込んだ図の組を範囲にする。検索(ツールバー)は表示していない図の当たりを
   図と行で並べて押すとその図を開き、プロパティ欄の ID の改名はほかの図が同じ ID を使っていれば全部に planRename を当てる。
   「.sb 保存」は表示中の図と、変わったほかの図をそれぞれのファイル名で続けて書き出す
3. 新しい「フォルダ」パネルを作る(owner の指定に反する)

## 決定
案 2。計算は CLI・VSCode と同じ core/label(planRename / findIdInDsl と、検索用に足した searchIdsInFiles)。どこかの図で改名できなければ
(改名先が既にある・1 枚の中で重複定義)どの図も変えない。図の切替と図をまたぐ改名は、全部の図の本文を 1 段として ↩ で戻す。
あわせて renameIdInDsl は、ラベル全体が旧 ID と同じ文字列(ID をそのまま表示名にしている)ときだけ表示名も新 ID に揃える
(ID と表示名の食い違いは利用者の現場でレビュー指摘になる)。CLI・VSCode の改名も同じ core なので同じ結果になる。

## 影響
- 保存が複数ファイルのダウンロードになる。ファイル名は読み込んだ名前(フォルダの部分は落ちる)。Chrome は初回に「複数ファイルのダウンロード」の許可を求める
- 範囲は一緒に読み込んだ図だけ。読み込んでいない図は探さず、変えない(CLI の `npm run check -- --refs / --rename` はフォルダ全体)
