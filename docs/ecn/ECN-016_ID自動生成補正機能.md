# ECN-016: ID自動生成・補正機能

- **ステータス**: 適用済
- **種別**: 機能追加
- **対象コミット**: `8c5946c`, `bdcc074`, `465aceb`, `6d48a3f`
- **影響ファイル**: `stableblock.html`, `vscode-stableblock/src/extension.js`

## コンテキスト

ブロック追加・ペースト時に `block_1`, `block_2` のような汎用IDが生成され、図が大きくなるとIDからブロックを特定できなくなっていた。また、コピー&ペーストで重複IDが発生し、ドラッグ時に意図しないブロックが移動する問題があった。

## 対策

### 1. プレースホルダID方式 (`8c5946c`)

新規ブロック・グループの追加時、即座にIDを確定するのではなく `__new_N` 形式のプレースホルダIDを割り当てる。ツールバーの「ID補正」ボタンでラベルからIDを一括生成する。

- `labelToId()`: ラベルを小文字化、特殊文字除去、スペースをアンダースコアに変換
- `fixNames()`: `__new_` プレフィックスのIDをラベルベースIDに置換、重複時は `_N` サフィックス付与
- 接続線中のID参照も自動更新

### 2. ID長の制限 (`bdcc074`)

長いラベルから生成されるIDが冗長になる問題に対し、`labelToId()` の出力を30文字に制限。末尾のアンダースコアもトリミング。

### 3. 全ID一括リネーム (`465aceb`)

「ID補正」ボタンのShift+クリックで、`__new_` プレフィックスに限らず全ブロック・グループ・ノートのIDをラベルから再生成する隠し機能。パワーユーザー向けのためUIインジケーションなし。

### 4. 重複ID検出 (`6d48a3f`)

パーサーに重複IDの検出を追加。全要素のIDを `allIds` オブジェクトで管理し、重複発見時にエラーバーに行番号付きで報告。

```
エラー表示例: ID "sensor" が重複 (L3)
```

## 設計判断

- **プレースホルダ方式を採用した理由**: ブロック追加時にラベルが未入力なことが多く、追加と同時にIDを確定するとラベル変更時にIDとの不整合が発生する。ラベル入力後の一括補正方式が最も実用的。
- **30文字制限の根拠**: DSLテキストの可読性とIDのコピー&ペースト操作性のバランス。

## 効果

- IDが内容を反映した意味のある名前になり、DSLの可読性が向上
- 重複IDが早期検出され、ドラッグ操作の誤動作を防止
