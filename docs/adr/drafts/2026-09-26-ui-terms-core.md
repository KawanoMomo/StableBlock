# [DRAFT] 画面の入口の名前・ツールチップを core/terms に 1 か所で決める

- ステータス: ドラフト(未採番。承認後 /adr で正式登録)
- 日付: 2026-09-26
- 起点: BLK-owner-20260925-1921-7(ツールバーとパネルの用語・表記が揃っていない、README が実在しないものを案内している)

## コンテキスト
ツールバーとプロパティ欄の入口の名前が HTML 版と VSCode 拡張で別々に書かれ、略語(「HL」)・絵文字だけ(「📋」)・現在の値だけ(「⌇ 曲線」)・
表記揺れ(「PNG透過」と README の「透過PNG」、「＋ ブロック追加」と「+ ブロック追加」)・英語の選択肢(`solid / dashed / bold`)が混在していた。
ECN-017(ハイライトモード)が入れた「HL」ボタンもこの一つ。

## 選択肢
1. 各実装の文字列をその場で直す
2. `core/terms/terms-core.mjs` に語彙表(入口キー → 表示名・ツールチップ、ja / en)と、スタイル・線の形・種類の表示名を返す純粋関数を置き、
   HTML 版は `terms-core.browser.js`(window.StableBlockTerms)、拡張は Webview へのインライン埋め込みで同じ表を使う
3. 2 に加えて、静的な入口も実行時に語彙表から描く

## 決定
案 2。静的に書いた入口は `data-term="キー"` を持ち、その文字と title が語彙表と一致することを `core/terms/__tests__` が node --test で守る
(実行時に描き替えない = 案 3 は採らない。file:// で語彙の読込に失敗しても入口の名前が残る)。動的に描く部分(線の形ボタン、
プロパティ欄の種類・スタイル・線の形)は実行時に語彙表の関数を呼ぶ。README のファイル構成に書いた名前が実在することも同じテストで守る。
- 名前は「何をするか」: 「◎ 未接続を薄く」「PNGをコピー」「透過PNG」「⌇ 線の形: 曲線」(何を切り替えるか + 今の値)
- ツールチップは動詞で言い、ショートカットを括弧で添える
- グループ欄の追加は「+ グループ内にブロック追加」(ツール欄の「+ ブロック追加」と別の働きなので別の名前、半角 +)

## 影響
- 入口の名前を E2E で押している spec は名前を追う(junior-02 のグループ内追加)
- 拡張は英語の同じ意味の語(Dim unlinked / Show notes / Copy PNG / Transparent PNG)
