# [DRAFT] 接続ラベルを block より上の層に描き、既定の置き場所を core で選ぶ

- ステータス: ドラフト(未採番。承認後 /adr で正式登録)
- 日付: 2026-09-26
- 課題: BLK-owner-20260926-0451-2(1 グリッド間隔の図で 10 本中 7 本のラベルが block の下に隠れる)

## コンテキスト
接続ラベルは線と同じ層(block より下)に、中点の右(lpos の既定)へ描いていた。block を既定の 1 グリッド間隔で並べると、
中点の右は隣の block の上になり、画面・SVG・PNG では block に塗りつぶされ、Excel ではラベルのテキストボックスが block より下の z 順に出る。
隠れていることは何も知らせなかった。

## 選択肢
1. 層だけ変える: ラベルを block より上に白地で描く(draw.io / Visio と同じ)。置き場所は今のまま
2. 置き場所だけ変える: 隠れる位置なら別の位置へ逃がす。層は今のまま
3. 両方: ラベルは block より上に描き、本文に `lpos=` が無いラベルは、block の地・block の名前・group の見出し・note・先に置いたラベル・
   キャンバスの外への掛かりが最も小さい候補(右 → 上 → 左 → 下 → 中央)を選ぶ。`lpos=` があればその位置のまま。
   避けきれず名前・見出し・他のラベルに掛かる、note の下に隠れるときは警告に出す
4. 警告だけ出す(描き方は変えない)

## 決定
案 3。案 1 だけでは上に出たラベルが block の名前を塗りつぶし、案 2 だけでは逃げ場の無い隙間で隠れる。案 4 は利用者に座標の手直しを強いる。
置き場所の計算は `core/label/label-core.mjs` の `placeLabels` / `labelIssues` に置き、HTML 版・VSCode 拡張の描画と、`core/check`
(画面の警告・`npm run check`)が同じ計算を使う。本文・座標は変えない(置き場所は描画時の計算。本文に `lpos=` を書けば固定される)。
隙間が広く中点の右が空いている既存の図は、今までどおり右に描かれ見た目が変わらない。

## 影響
- Excel: 接続ラベルの z 順を block より後(note より前)にした。置き場所は従来どおり直線の中点(emitter は label-core を読み込めないため)
- 接続の parser は `lposAuto`(本文に `lpos=` が無い)を持つ。HTML 版・dsl-core・拡張の 3 つの parser で同じ
- 文字幅は描画側が実測値を渡し、検査(node)は見積もり(ASCII 0.6 字幅・全角 1 字幅)を使うため、境目の図で警告の有無が僅かに違いうる
