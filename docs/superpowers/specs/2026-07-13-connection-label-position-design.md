# 接続線ラベルのUI入力・位置指定・背景 設計スペック

- **日付**: 2026-07-13
- **ステータス**: レビュー待ち
- **対象**: `stableblock.html`(HTML版)、`vscode-stableblock/src/extension.js`(VSCode拡張)

## 背景 / 課題

現状の接続線ラベルには3つの課題がある。

1. **UIから入力できない** — DSLでは `ui -> comm "payload"` の形でラベルを記述できるが、プロパティパネルの接続セクション(2ブロック選択時)には反転/双方向/色/太さ/スタイル/経路/削除しかなく、ラベルの入力・編集欄がない
2. **線と重なって読みづらい** — ラベルは始点・終点の中点(y−5px)に背景なしで描画されるため、線と重なる
3. **曲線で位置がずれる** — 基点が「弦の中点」なので、ベジェ曲線では線から浮いた位置にラベルが出る

## 決定事項(ユーザー確認済み)

| 論点 | 決定 |
|---|---|
| 位置の基準 | **画面座標基準**(線の中点から見て画面上の右/左/上/下) |
| デフォルト位置 | **右**。位置未指定の既存ラベルも右表示に変わる(既存図の見た目変更を許容) |
| 背景の適用範囲 | **全位置モード共通** |
| 背景方式 | **白角丸矩形**(Mermaid風)。テキスト幅は Canvas measureText で計測 |
| 入力UI | **既存の2ブロック選択→接続セクションに追加**(線クリック選択は将来拡張) |
| 反映スコープ | **SVG系のみ**(HTML版+VSCode拡張)。Excelエクスポートは現状維持 |

## 1. DSL構文拡張

```
ui -> comm "payload"              # 位置未指定 → 右(新デフォルト)
ui -> comm "payload" lpos=center  # 中央(従来位置)を明示
ui -> comm "payload" lpos=top     # 5値: right / left / top / bottom / center
```

- 属性名は `lpos=`。既存の接続属性(`color=` `style=` `width=` `route=`)と同じ `key=value` 形式で、接続行の正規表現マッチ(rest部)から抽出する
- 未指定時のデフォルトは `right`
- 不正値(タイポ等)は `right` にフォールバックし、エラーにはしない(既存属性の寛容な扱いと整合)
- **後方互換**: Excelエクスポート(`core/excel/emitter.js`)と Mermaid変換は `lpos` を無視し従来動作を維持する。パーサーがフィールドを追加しても出力系が参照しないだけなので破壊的変更はない

## 2. ラベル基点 = 描画パスの幾何中点

現状の「弦の中点」を廃止し、経路(route)ごとに描画パスの幾何中点を解析的に計算する。DOM計測(getBBox / getPointAtLength)は使わない(文字列連結でSVGを生成する現アーキテクチャのため)。

| 経路 | 中点計算 |
|---|---|
| straight | 弦の中点(現状同等) |
| curved | 3次ベジェの t=0.5 点 = (P0 + 3·C1 + 3·C2 + P3) / 8。制御点は `bP()`/`bpath()` が算出するものと同一値を使う |
| ortho | 折れ線の全長の1/2地点。頂点列は `orthoPath()` が生成するものと同一値を使う |

パス文字列生成と中点計算で制御点・頂点の計算を共有し、二重実装によるズレを防ぐ(パス生成関数が「パス文字列+中点」を返す形にリファクタする)。

## 3. 位置オフセット仕様(画面座標基準)

基点(幾何中点)からのオフセットと文字アンカー:

| lpos | オフセット | text-anchor | dominant-baseline |
|---|---|---|---|
| right | x +10px | start | central |
| left | x −10px | end | central |
| top | y −10px | middle | auto(下端基準) |
| bottom | y +10px | middle | hanging |
| center | なし | middle | central |

- 現行の中央モードにある「y−5px」の小細工は廃止し、真の中点+背景矩形に置き換える
- フォントは現状踏襲: `font-size:10px, font-weight:500, fill=接続線色`

## 4. 背景矩形(全位置モード共通)

- オフスクリーン Canvas 2D の `measureText` でテキスト幅を計測する
  - フォント指定はSVG側と厳密に一致させる: `500 10px sans-serif`
  - Canvasコンテキストはモジュールスコープで1個生成して使い回す(ドラッグ中の再描画性能への影響を避ける。ECN-015の教訓)
- テキストの直前(SVG文字列上で先)に白角丸矩形を挿入する
  - `fill=#FFFFFF`、padding 横4px / 縦2px、`rx=2`
  - キャンバスは常に白地(`#svg-wrap { background:#fff }`)のため背景色は固定値でよい
- **既知の仕様**: PNG透過エクスポート時は白矩形がそのまま残る(Mermaidと同等の挙動として許容)

## 5. UI: プロパティパネル接続セクション拡張(両実装)

2ブロック選択時の接続セクション(既存接続がある場合)に以下を追加する:

```
┌─ 接続 ────────────────┐
│  ui → comm               │
│  [⇄ 反転] [↔ 双方向]      │
│  ラベル: [payload______]   │ ← 新規: テキスト入力欄
│  位置: [右][左][上][下][中央] │ ← 新規: 5ボタン、現在値ハイライト
│  線の色: ●●●●●● …        │
└──────────────────────┘
```

- **ラベル書き戻し**: 接続行の `"..."` 部分を置換する専用関数を新設。ラベルが未設定の接続には `from -> to` の直後(既存属性 `color=` 等がある場合はその前)に `"label"` を挿入する
- **位置書き戻し**: 既存の接続属性書き戻し(HTML版 `setConnProp` / 拡張版 `setCP`)を `lpos` にそのまま利用。`center` 選択時も `lpos=center` を明示付与する(デフォルトが right のため)
- **ECN-003対策(フォーカス喪失)**: ラベル入力の `oninput` ではプロパティパネルを再構築せず、DSL書き戻し+SVG再描画+エディタ同期のみ行う(既存ブロックラベル `setLabel` と同じ構造)
- **ECN-002対策(空ラベル)**: 入力欄を空にした場合はDSLから引用符ごとラベルを除去し、接続自体は保持する

## 6. スコープ外(将来拡張)

- Excelエクスポートへの位置・背景反映(後続ECNで横展開判断)
- Mermaid変換への位置反映(Mermaid側に対応概念がない)
- 接続線の直接クリック選択+専用プロパティパネル
- HTML版と拡張版のレンダラ共通化リファクタ(コピー型アーキテクチャは維持。実装は HTML版で確立→拡張版へ移植の順)
- MCPサーバー(`mcp-server/`)は DSL文字列を透過的に扱うため影響なしの見込み。実装計画に確認タスクを1件置く

## 7. 検証方針

- **ロジック**: パーサーの `lpos` 抽出(5値+未指定+不正値)、経路別の幾何中点計算(straight/curved/ortho)、ラベル書き戻し関数(置換・挿入・空文字除去)を単体で確認
- **UI/描画**: evaluator(Playwright)による実機スクリーンショット検証を必須とする(visual verification gate)
  - 5位置 × 3経路の見た目
  - ラベル入力中のフォーカス保持(ECN-003再発防止)
  - 空文字入力でラベルのみ消え接続が残ること(ECN-002再発防止)
  - 位置未指定の既存図がデフォルト右で表示されること
  - 日本語ラベルで背景矩形の幅が合っていること
- HTML版・VSCode拡張の両方で検証する

## QAログ(推奨案で先行決定した非クリティカル論点)

| # | 論点 | 決定 | 理由 |
|---|---|---|---|
| 1 | DSL属性名 | `lpos=` | 既存の短縮命名(`route=`等)と整合 |
| 2 | オフセット量/padding | 10px / 横4px縦2px / rx=2 | フォント10pxに対する標準的な余白 |
| 3 | 背景色 | #FFFFFF固定 | キャンバスが常に白地のため |
| 4 | 基点 | 弦中点→パス幾何中点 | 曲線でラベルが線に乗る。解析解で計算可能なことを確認済み |
| 5 | PNG透過時の白矩形残り | 許容 | Mermaid同等の挙動 |
| 6 | 中央モードのy−5px | 廃止 | 背景矩形導入で不要になる |
| 7 | 不正なlpos値 | rightにフォールバック | 既存属性の寛容な扱いと整合 |

## 技術的裏付け

- 3次ベジェ中点の解析解、折れ線半長点は純粋な数値計算で文字列生成時に算出可能(確認済み: `bP()` は `M f C c1 c2 t` 形式の3次ベジェ、`orthoPath()` は頂点列既知の折れ線)
- Canvas `measureText` は日本語混在テキストでも正確な幅を返し、オフスクリーンで高速
- 参考: SVGテキスト視認性の代替案として `paint-order: stroke`(白縁取り)も検討したが、ユーザー確認により矩形背景を採用([MDN paint-order](https://developer.mozilla.org/en-US/docs/Web/SVG/Reference/Attribute/paint-order))
