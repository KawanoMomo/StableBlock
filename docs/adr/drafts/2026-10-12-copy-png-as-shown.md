# ADR ドラフト: 「PNGをコピー」は画面の見た目(薄め・注釈の表示)のまま描く

- 状態: ドラフト(採番は人間)
- 関連: BLK-human-20261012-1432-1(人間の所感: クリップボードのコピーが画面の見た目を保持しなくなった)、
  `2026-09-26-render-core-export.md`(書き出しは画面の状態を持ち込まない)、ECN-017(ハイライトモード。当初は書き出しにも薄めが入った)

## コンテキスト
ECN-017 の時点では SVG / PNG / コピーは画面の SVG を直列化していたので、「◎ 未接続」の薄めが画像にも入り、資料に
「依存の無い部品を薄くした図」を貼れた。render-core-export(BLK-owner-20260926-0609-1)で書き出しを本文だけの絵に揃えたとき、
選択の枠・ハンドル・グリッド・倍率と一緒に薄めも落ちたため、人間から見ると「クリップボードのコピーが見た目どおりでなくなった」退行になった。

## 検討した案
1. 画面の SVG を直列化する方式に戻す — 選択の枠・ハンドル・グリッド・倍率がまた入る(render-core-export で直した不具合の再発)
2. 全部の書き出し(SVG / PNG / 透過PNG / コピー / 一括)に薄めを持ち込む — 「同じ本文から同じ絵」が崩れ、一括書き出しや reviewer の SVG 検査が画面の状態で変わる
3. **core/render に `viewExportSvg(parsed, view, …)` を足し、薄め(highlight・search)と注釈の表示切替だけを view から受け取る。
   選択・ハンドル・スナップガイド・グリッド・見比べの印・倍率は持ち込まない。「PNGをコピー」がこれを使う** — 採用

## 決定
- `viewExportSvg` は薄めも注釈を隠すことも無い画面では `exportSvg` とバイト一致(unit で確かめる)
- 「PNGをコピー」(HTML 版・VSCode 拡張)は viewExportSvg。コピー後のステータスバーに、持ち込んだ見た目(未接続を薄く・検索の薄め・注釈を隠す)を出す
- 「PNG」「透過PNG」「SVG」の保存、一括書き出し、Excel / Mermaid はこれまでどおり本文だけ(保存側に薄めを入れるかは BLK-human-20261012-1432-2 で決める)

## 影響
- 「◎ 未接続」を付けたままコピーすると、貼った画像でも未接続の要素が薄い(意図した見た目)。本文だけの絵が欲しければ「◎ 未接続」を外してコピーするか「PNG」で保存する
